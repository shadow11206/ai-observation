# 飞书知识库结构说明

> 对应 GitHub 仓库：ai-observation
> 核心原则：用得到才看，结构扁平，最多 2 层深度

---

## 设计理念

这个知识库不是"收藏夹"，而是"我的判断备忘录"。

**使用场景**：
- 写公众号文章前 → 打开"我的核心判断"，看我对这个话题的当前立场
- 有人问某个话题 → 3 秒内找到我的答案
- 要触发深度调研 → 查"我的核心判断"，看哪个问题还需要更多证据

---

## 各板块说明

### 🎯 我的核心判断

**本质**：一个活文档，记录你对 AI 行业关键问题的实时判断。

**每个文件的结构**（直接复制 `templates/opinion-log-template.md`）：
```
核心问题：[标题]
---
当前判断：[2-3句话，你现在的立场]
---
更新记录：[时间倒序，每次有新信息就追加]
```

**触发更新的时机**：
- 每次深度调研完成后，必须更新对应的核心判断文件
- 看到日报里"值得深挖"的话题被确认时
- 有信息让你觉得"这改变了我的看法"时

**建议初始核心问题**（4-6 个即可，不要贪多）：
1. AI Agent 真正落地的时间线是什么？
2. 大模型的竞争格局会如何演变？
3. AI Coding 工具对开发者意味着什么？
4. AI 对产品经理职业有什么实质影响？

---

### 📰 深度调研归档

**本质**：深度调研报告的摘要版，按"影响了哪个判断"来索引。

**不是**：完整报告的备份（完整报告在 GitHub `02-deep-research/`）

**每篇格式**：
```
标题：2026-03｜字节AI产品全景分析｜→ 影响「大模型竞争格局」判断

内容：
结论（3句话）：...
修改了哪个核心判断：[链接到「我的核心判断」对应文件]
完整报告：[GitHub 链接]
```

---

### 🔭 追踪名单

**本质**：和 GitHub `03-tracking-registry/` 保持同步，飞书里的是可读版本。

**建议**：不需要频繁更新，每月 Review 一次即可。

---

### ✏️ 待写素材

**本质**：公众号文章的素材池，不是已发文章的归档。

**使用方式**：
1. 每次深度调研完成，如果适合写文章，在这里加一条
2. 每周看一眼，选最有价值的一条开始写
3. 文章发布后，这条素材移入飞书文档"已发布"归档

---

## 与 GitHub 仓库的对应关系

| 飞书知识库 | GitHub 仓库 | 说明 |
|---------|-----------|------|
| 我的核心判断 | `04-opinion-log/` | 双向维护，飞书是主要阅读入口 |
| 深度调研归档 | `02-deep-research/` | 飞书存摘要，GitHub 存完整报告 |
| 追踪名单 | `03-tracking-registry/` | GitHub 是 source of truth |
| 待写素材 | 无对应 | 仅飞书维护 |
| **日报** | `01-daily-reports/` | **日报不进飞书**，只在 GitHub 归档 |

---

## 搭建步骤（第一次建立）

1. 在飞书中新建独立知识库，命名"AI Observation"
2. 按上面的目录结构创建 4 个一级页面
3. 在"我的核心判断"下创建 4-6 个初始问题文件
4. 在每个问题文件中写下你的初始判断（哪怕只有一句话）
5. 把 GitHub `03-tracking-registry/` 的内容复制进来

第一次建立时不要追求完整，能用起来最重要。
